# 質問: 未コミットの記録ファイルをどうコミットするか

Code Generation（U2・U3の実装）を始める前に、AI-DLCのツールが「記録ファイルがコミットされていない」として処理を拒否しました。未コミットなのはアプリのコードではなく、ここまでのNFR Design・Infrastructure Design・Code Generation計画などの記録ファイル（`aidlc/`配下）と`docs/05-construction.md`です。

## A. main に直接コミットする

- 利点: すぐにブロックが解除され、Code Generationに進める
- リスク: team.mdで決めた「作業はすべて作業ブランチで行い、毎回PRを作ってGitHubの画面で確認してから取り込む」というこのプロジェクト自身のルールに反する。このルールは「1人での開発だが、確認の手順を残し、動画教材でPR画面を見せるため」という明確な理由で決めたもの（Q1の理由）。GitHub Actions（CI）のチェックも、PR画面での差分確認も経ずにmainの履歴に残る。一度コミットすると、取り消すには別の取り消し操作（revertなど）が必要になる。

## B. 作業ブランチ＋PRにする

- 利点: team.mdのルールどおりで、これまでの2つのPR（#1・#2）と同じ、きれいな履歴が保てる。動画教材用の「PR画面を見せる」という目的にも合う
- コスト: ブランチを切ってpushし、PRを作る手間が増える。さらに、GitHubでそのPRを確認して取り込む（マージする）作業が必要になる。これを私が代わりに行ってよいか、それともご自身でGitHub画面で確認してから取り込みたいか、という追加の判断も必要になる

[Answer]:A
