# CI/CD Pipeline（ビルド・試験・デプロイの流れ）— U3 `u3-review-list`

入力: `construction/u1-skeleton/infrastructure-design/cicd-pipeline.md`（U1 の流れ。そのまま使う）、infrastructure-specification.md、monitoring-design.md、`construction/u3-review-list/nfr-requirements/tech-stack-decisions.md`（NFR13.9・NFR13.10）。

U1 の流れ（手元の確認 → PR → CI → 取り込み → デプロイ前の確認 → デプロイ → スモーク → タグ）は変えない。U3 で足すのは CI の試験内容とスモークの手順のみ。新しいスタック・リソースがないため、デプロイ前の確認・戻し方の手順に変更はない。

## 1. CI（AWS に接続しない）での追加

| 対象 | 試験の内容 |
|---|---|
| 単体試験 | 却下・取り消しの条件付き書き換え（ConditionExpression）のロジック、絞り込みの判定ロジック、`undoUntil` の絞り込み（本人かつ期限内）のロジック |
| 結合試験 | DynamoDB Local で `ReviewDecisions`・`ReportListItems` への新しい項目の読み書きを確認する。同時に 2 つの書き換えをほぼ同時に起動して 1 回だけ成功することを確認する（NFR13.9） |
| 単体試験（時刻） | 取り消しの期限の試験は `vi.useFakeTimers()` で時刻を進めて確認する（NFR13.10） |
| E2E（AWS なし） | 却下の理由選択、取り消しボタンの表示・消失、絞り込みの操作、同時操作で弾かれたときの画面表示 |
| CDK の構成の試験 | `review`・`catalog` 関数のメモリ・時間切れが変わっていないこと、新しいテーブルや関数が作られていないこと、`catalog` 関数が `ReviewDecisions` への権限を持たず、`review` 関数が `ReportListItems` への権限を持たないこと（IAM の境界が部品ごとに保たれていること）を確認する |

## 2. デプロイ前の確認

U1 の「`cdk diff --all` の結果と費用の見込みを示す」をそのまま行う。U3 は新しいリソースを作らないため、`cdk diff` の差分はコードの更新（関数のデプロイパッケージの変更）のみで、リソースの追加・削除は現れない見込み。

## 3. スモーク（U3 で足す手順）

U1・U2 のスモークのあとに続けて行う:

| # | 内容 |
|---|---|
| 12 | 試験用の依頼元で、確認中の報告を却下する（理由を選ぶ）。10 秒以内に「取り消す」ボタンが表示されることを確認する |
| 13 | 「取り消す」を押し、確認中に戻ることを確認する |
| 14 | 絞り込み（状態・印）を指定して一覧を読み、条件に合う行だけが返ることを確認する |
| 15 | 2 つのブラウザセッション（または 2 回の並行リクエスト）で同じ報告を同時に承認・却下し、1 回だけ成功し、もう一方が「すでに確認済みです」と表示されることを確認する |
