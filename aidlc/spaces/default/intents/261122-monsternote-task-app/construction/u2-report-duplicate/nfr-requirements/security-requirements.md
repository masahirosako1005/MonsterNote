# Security Requirements（セキュリティの要件）— U2 `u2-report-duplicate`

入力: `construction/u1-skeleton/nfr-requirements/security-requirements.md`（U1 の NFR4.1〜NFR6.3。U2 はこれを引き継ぐ）、`construction/u2-report-duplicate/functional-design/`（rules の BR2・BR6・BR7・BR8・BR9、functional-spec）、`inception/requirements-analysis/requirements.md`（NFR4・NFR5・NFR6）、`inception/domain-design/decisions.md`（ADR-011 部品の身元の証明）、`inception/contract-design/contract-summary.md`（C2・C5・C8・C9・C11・C16、2.1・2.1b）、nfr-requirements-questions.md（Q1〜Q6）、project.md。

## 1. 認証と認可（U2 で足すもの）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR4.6 | 判別の結果を読めるのは、その写真を送ったハンターだけ。ほかの人の写真の ID を指定しても返さない | 単体試験（他人の写真の ID で 403） | NFR4、BR6.5 |
| NFR4.7 | 重複の疑いの相手の一覧（`GET /v1/duplicates/{id}`）を読めるのは依頼元だけ。ハンターは 403 | 単体試験 | NFR4、BR8.9 |
| NFR4.8 | 設定の読み出し（`GET /internal/v1/settings`）は、ログインしている利用者の証明と、部品の身元の証明の**両方**を受け付ける（保存のあとの再判定には利用者の証明がないため）。それ以外は拒む | 単体試験（証明なしで 401、部品の身元の証明で 200） | NFR4、BR9.1、contract-summary 2.1b |
| NFR4.9 | 内部の道（`/internal/v1/species-detections`・`/internal/v1/duplicate-checks`）は外の API の入口に出さない | CDK の構成の試験（外の入口にこれらの道がない） | NFR4、ADR-011 |

## 2. データの保護（U2 で足すもの）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR5.7 | **ハンターに見せる重複の知らせには、相手の種類・捕獲日時・おおよその距離（100 m 単位）だけを入れる。** 相手の報告の ID・ハンターの ID・氏名・写真は入れない（自分の報告が相手のときも同じ） | 単体試験（応答の項目を確かめる）、E2E | NFR5、FR7.1、BR7.3 |
| NFR5.8 | 重複の判定に使う索引（ReportFootprint）には、種類・場所・日時・ハンターの ID だけを持ち、**氏名・写真・報告の中身は持たない** | 単体試験、データの形の確認 | NFR5、BR8.1 |
| NFR5.9 | 判別の結果（DetectionResult）に、写真そのものは持たない（写真の ID だけを指す） | データの形の確認 | NFR5 |
| NFR5.10 | ログに、捕獲場所の緯度・経度、写真の保存場所のキー、判別のサービスが返した生のラベルを出さない（U1 の NFR5.5 に足す） | 単体試験（ログの出力に含まれないこと） | NFR5、U1 の NFR5.5 |
| NFR5.11 | 外部の画像認識のサービスに送るのは、**写真の保存場所の参照だけ**（画像の中身を自分のサーバーで持ち回らない）。サービス側に写真が保存されない設定で使う | 設計の確認、CDK の構成の試験 | NFR5 |
| NFR5.12 | 地図の表示に使う外部のサービス（タイル）には、**捕獲場所の緯度・経度を送らない**（画面が表示する範囲の座標は送るが、報告の内容とは結び付けない）。地名を求める外部のサービスは使わない | 設計の確認 | NFR5、機能設計の Q2 |

## 3. 秘密情報（U2 で足すもの）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR6.4 | 外部の画像認識のサービスは、関数に付けた権限（IAM ロール）で呼ぶ。鍵やトークンを持たない | CDK の構成の試験 | NFR6、project.md |

## 4. 脅威の考慮（U2 で足すもの）

| 脅威 | 手当て |
|---|---|
| 送信の前の知らせから、他人の報告の場所を推測される | 距離を 100 m 単位に丸める（NFR5.7・BR7.3） |
| 他人の写真の ID を自分の報告に使う | 写真の持ち主と 24 時間以内の確認（BR2.3・BR2.14） |
| 写真を送らずに報告だけを作る | アップロードの完了の確認（BR2.9）と必須の写真の確認（BR2.17） |
| クマ以外の報告に胸の写真を付けて、別の報告の写真を使い回す | 種類と写真の組み合わせの確認（BR2.18） |
| 判別のサービスを大量に呼んで費用を増やす | 1 人のハンターにつき 1 日 30 回までの上限（Q2・NFR12.5） |
| 重複の判定で大量の記録を読ませて費用を増やす | 1 回の判定で 500 件までの上限（Q4・NFR12.6） |
| 対象地域の外から報告を送る | 画面とサーバーの両方で確かめる（BR2.16） |
| 偽の知らせで索引や疑いを作る | 知らせの受け口を外に出さない（NFR4.9、NFR Design） |

## Assumptions & Open Questions

- NFR5.11 の「サービス側に写真が保存されない設定」は、AWS の画像認識のサービスの既定の動作（結果を学習に使わない設定）を使う。契約や設定の具体は Infrastructure Design で確かめる。 [assumption]
- NFR5.12 の地図のタイルは、画面が表示している範囲の座標を外部に送る（地図を出すために避けられない）。報告の捕獲場所そのものを送るわけではないが、ハンターが地図を動かした範囲は外部に伝わる。試験運用の規模では許容する。 [assumption]
- 判別のサービスが返した生のラベル（`rawLabels`）は記録には残すが、ログには出さない（NFR5.10）。あとで基準を見直すための材料。 [assumption]
