# Security Requirements（セキュリティの要件）— U4 `u4-accounts-admin`

入力: `construction/u1-skeleton/nfr-requirements/security-requirements.md`（U1 の NFR4.1〜NFR6.3。U4 はこれを引き継ぐ）、`construction/u4-accounts-admin/functional-design/`（rules の BR11・BR12・BR13）、`inception/requirements-analysis/requirements.md`（NFR4・NFR5・NFR6）、`inception/contract-design/contract-summary.md`（C1・C7・C17）、nfr-requirements-questions.md（Q1〜Q3）、project.md。

## 1. 認証と認可（U4 で足すもの）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR4.13 | 管理者の画面・API（`/v1/admin/...`）は、役割が admin の証明だけを受け付ける。ハンター・依頼元は 403（U1 の NFR4.3 を管理者の道にも適用） | 単体試験（他の役割で 403） | NFR4、BR11.1 |
| NFR4.14 | 管理者は自分自身を無効にできない。有効な管理者が 1 人だけのときは、その管理者も無効にできない（BR11.9 の条件付き書き換えで確かめる） | 単体試験（自分自身・最後の 1 人の両方で 422） | NFR4、BR11.9 |
| NFR4.15 | 仮のパスワードのアカウント（`mustChangePassword=true`）は、パスワードの変更と自分のアカウントの読み出し以外のすべての操作を拒む | 単体試験 | NFR4、BR11.4 |
| NFR4.16 | 管理者のログインの失敗が続いたときの扱いは、U1 の NFR4.5（認証のサービスの標準の保護）と同じにする。管理者だけの追加の仕組みは設けない | 設計の確認 | NFR4、Q1 |
| NFR4.17 | 「すべて削除」の 5 つの入口は、役割が admin であれば誰でも実行できる（追加の権限の階層は設けない） | 単体試験 | NFR4、Q2、BR13.3 |

## 2. データの保護（U4 で足すもの）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR5.15 | 仮のパスワードは、応答に 1 回だけ入れて返す。保存も記録（操作の記録を含む）もしない | 単体試験（記録に仮のパスワードの文字列が含まれないこと） | NFR5、BR11.3 |
| NFR5.16 | 操作の記録（AuditEntry）には、パスワード・写真そのもの・報告の中身・却下の理由の文を入れない。表示名（actorName）だけを持つ | データの形の確認、単体試験 | NFR5、BR12.3 |
| NFR5.17 | ログに利用者の ID（accountId）をそのまま出さない。確認した人・操作した人は表示名（無ければ役割の呼び名）で示す（U1〜U3 の決まりを管理者の操作にも適用） | 単体試験（ログの出力の確認） | NFR5、U1 の NFR5.5、BR3.12・BR11.2 |

## 3. 秘密情報

最初の管理者を作るスクリプトの秘密情報の扱いは、U1 の NFR6.3（開発者の手元の AWS の認証情報を使い、仮のパスワードは画面に 1 回だけ表示する）のままで、U4 で変える点はない（スクリプトに `admin` の役割を足すだけで、秘密情報の扱いの決まりは増えない。レビュー R-02）。

## 4. 脅威の考慮（U4 で足すもの）

| 脅威 | 手当て |
|---|---|
| 管理者を全員無効にして、誰も管理の画面に入れなくする | 自分自身・最後の 1 人は無効にできない（NFR4.14） |
| 仮のパスワードをログや記録に残す | 保存も記録もせず、応答に 1 回だけ（NFR5.15） |
| 「すべて削除」を誤って・悪意で実行する | 件数つきの確認画面（NFR7.9）、操作は必ず記録に残る（BR13.4） |
| 無効にした管理者が、証明の期限内に管理の操作を続ける | U1 の NFR10.4 のとおり、期限（1 時間）が切れれば出し直せない（即時の締め出しではない） |
| 操作の記録から利用者を特定できる個人情報を集める | 記録には表示名だけ。氏名・住所・写真は入れない（NFR5.16） |

## Assumptions & Open Questions

- NFR4.14 の「最後の 1 人」の判定は AdminCounter を使う（機能設計の BR11.9）。この記録の整合性そのものは NFR の目標にしない（Q3）。 [assumption]
