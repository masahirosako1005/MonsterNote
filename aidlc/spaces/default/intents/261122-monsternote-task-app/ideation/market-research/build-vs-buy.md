# Build vs Buy — MonsterNote

前提: `ideation/intent-capture/intent-statement.md`（intent-statement）。きっかけは AI-DLC2 の教材化と、AWS サーバレスを無料枠内で作る練習である。

## 1. 選択肢

| 選択肢 | 内容 |
|---|---|
| Build（自分で作る） | MonsterNote を一から作る |
| Buy（既存製品を使う） | スマートHOKAKU、ラクログ、ディアナなど既存の捕獲報告アプリを導入する（[農林水産省 機器情報](https://www.maff.go.jp/j/seisan/tyozyu/higai/kikijouhou/kikijouhou.html)） |
| Partner（連携） | 自分で作り、既存製品とデータをやり取りする |

## 2. 評価

スコア: Build に有利なら +、Buy に有利なら −（−2〜+2）

| 観点 | Build | Buy | スコア |
|---|---|---|---|
| 目的との合致 | AI-DLC の学習・教材化という目的を直接満たす | 学習・教材の目的を満たせない | +2 |
| 差別化（重複検出・高齢者向け操作） | 自由に作り込める | 公開情報では重複検出は確認できない | +1 |
| 早く使い始められるか | 作る時間がかかる | すぐ使える | −2 |
| 費用 | 運用費は月 100 円以内が目標。作る手間は自分の時間 | 料金は公開情報から不明 | 0 |
| 圏外での利用などの成熟度 | 一から作る必要がある | 既存製品の多くが対応済み | −1 |
| 保守の負担 | 自分で保守する | 提供元が保守する | −1 |

合計: −1（純粋に業務で使うだけなら Buy がやや有利）

## 3. 結論

**Build（自分で作る）**。既存製品は参考にとどめる（market-research-questions.md の Q1）。

理由: このプロジェクトの第一の目的は、AI-DLC2 を使って作る過程を教材にすることである。業務で使うだけなら Buy がやや有利という評価だが、Buy ではその目的を満たせない。重複検出と高齢者向けの操作は、既存製品との差別化にもなる。

将来、勤務先のお客様（自治体）へ広げる段階では、既存製品と比べて選ばれる理由を改めて確認する（Q7）。
