# Wireframes（ラフな画面案）— MonsterNote 最初の版

入力: `ideation/intent-capture/intent-statement.md`（intent-statement）、`ideation/scope-definition/scope-document.md`（scope-document）、`ideation/scope-definition/intent-backlog.md`（intent-backlog）、rough-mockups-questions.md の回答（Q1〜Q8）。

## 0. 全体の方針

| 項目 | 方針 | 根拠 |
|---|---|---|
| デザイン | Google のマテリアルデザインに沿う | Q6 |
| 文字・ボタン（ハンター側） | 文字 20px 以上、ボタンは高さ 64px 以上・画面幅いっぱい、ボタンどうしの間隔 16px 以上 | Q5 |
| 色 | 色だけで意味を伝えない（文字とアイコンも付ける）。文字のコントラスト比 4.5:1 以上（WCAG 2.1 AA） | Q5 |
| 報告の作成 | 1 画面に 1 項目。各画面の大きなボタンは 1〜3 個。どの画面にも「戻る」がある | Q2 |
| ステップの表示 | 通常は 5 ステップ（全身・尻尾・種類・雌雄・確認）。クマのときは胸の写真が加わり 6 ステップになり、種類でクマを選んだ時点で表示を「n/6」に切り替える。重複の疑い（H7）と送信完了（H8）はステップに数えない | Q2・Q8 |
| メニュー | ハンター側の [Menu]: ホーム、ログアウト。依頼元側の [Menu]: 報告の一覧、ログアウト | — |
| 機器 | ハンター: スマホ・タブレットのブラウザ（縦向き優先）。依頼元: パソコンとスマホの両方 | intent-statement、Q4 |
| 対象の機能 | F1・F2・F3・F4・F6・F9・F10・F13（Must）。F7・F8（Should）の表示場所も用意する | scope-document、intent-backlog |

画面の図は低精細（箱と文字のみ）。表記: `[ ボタン ]`、`( 選択肢 )`、`<写真>`。

## ハンター側

### H1. ログイン／初回の登録

```
+--------------------------------+
| MonsterNote                    |
|                                |
| (Login ID)                     |
| (Password)                     |
|                                |
| [          Login           ]   |
+--------------------------------+
```

- 初回だけ続けて 2 画面: ① 同意（報告の氏名・位置・写真を依頼元と導入を検討する自治体に見せることへの同意。「同意する」「同意しない」）② 捕獲従事者の番号の入力（数字キーボード）。
- 状態: 読み込み中＝ボタンに読み込み表示 ／ エラー＝「ID かパスワードが違います」を入力欄の下に文字とアイコンで表示 ／ 同意しない＝利用できない理由と問い合わせ先を表示。
- アクセシビリティ: h1「MonsterNote」、ランドマーク header・main、最初のフォーカスは ID の入力欄。

### H2. ホーム

```
+--------------------------------+
| MonsterNote          [Menu]    |
|                                |
| [      + Report (big)      ]   |
|                                |
| My reports                     |
| - 11/20 Boar   [Approved]      |
| - 11/18 Deer   [Checking]      |
| - 11/15 Bear   [Rejected]      |
+--------------------------------+
```

- 一番上に大きな「報告する」ボタン（主な操作は 1 つだけ）。その下に自分の報告の一覧（日付・種類・状態）。状態は文字とアイコンで示す（下書き・確認中・承認・却下）。
- 「確認中」の報告には「送ってから n 日」を表示する。7 日を過ぎても確認中のときは「依頼元の確認に時間がかかっています。急ぐときは依頼元に連絡してください」と表示する（アプリからの催促や通知は最初の版では行わない）。
- 状態: 空＝「まだ報告はありません。上の『報告する』から始めます」 ／ 読み込み中＝一覧の形をした仮表示 ／ エラー＝「読み込めませんでした」と「もう一度」ボタン。
- アクセシビリティ: h1「ホーム」、h2「自分の報告」、ランドマーク header・main・nav、最初のフォーカスは「報告する」。

### H3. 写真を撮る（ステップ 1・2: 全身 → 尻尾。全体は 5、クマのときは 6）

```
+--------------------------------+
| Step 1/5  Whole body           |
|                                |
| <example picture>              |
| Write date and ID on the body, |
| then take the whole body.      |
|                                |
| [       Take photo         ]   |
| [ Back ]                       |
+--------------------------------+
```

- ステップ 1: 全身（体に書いたマーキングが写るように、と手本の絵で案内）。ステップ 2: 尻尾。撮った後は写真を大きく表示し、「この写真を使う」「撮り直す」の 2 ボタン。
- 撮影時に位置と日時を自動で取得する（画面には「位置を取得しました」と文字で表示）。位置の許可がないときは、許可の手順を表示する。
- 状態: 位置が取れない＝「位置情報をオンにしてください」と設定の手順 ／ 写真が暗い・ぶれている（判定できれば）＝撮り直しをすすめる。
- アクセシビリティ: h1「全身の写真」、ランドマーク main、最初のフォーカスは「撮影する」。手本の絵に代替テキスト。

### H4. 種類の確認（ステップ 3）

```
+--------------------------------+
| Step 3/5  Kind of animal       |
|                                |
| <whole body photo>             |
| This looks like: BOAR          |
|                                |
| [ Boar (selected)          ]   |
| [ Bear                     ]   |
| [ Deer                     ]   |
| [ Next ]            [ Back ]   |
+--------------------------------+
```

- 写真から判別した種類を選択済みで表示する（F3）。違うときは大きなボタンで選び直す。判別できなかったときは何も選ばれていない状態で「種類を選んでください」と表示。
- クマを選んだとき（判別・手動どちらでも）は、次に「胸（月の輪）」の撮影ステップを追加する（Q8）。
- 状態: 判別中＝「写真から種類を調べています」と進行表示（待ち時間が長いときは手で選べる）。
- アクセシビリティ: h1「種類の確認」、選択肢はラジオボタン相当（矢印キーで移動）、最初のフォーカスは選択済みの種類。

### H4b. 胸（月の輪）の写真（クマのときだけ、ステップ 4/6）

- H3 と同じ形（表示は「Step 4/6  Chest」）。「胸の月の輪が全部写るように」と手本の絵で案内する。月の輪の照合（F8）は Should のため、照合しない版でも写真は残す。
- アクセシビリティ: h1「胸の写真」、ランドマーク main、最初のフォーカスは「撮影する」。手本の絵に代替テキスト。

### H5. 雌雄の選択（ステップ 4/5、クマのときは 5/6）

```
+--------------------------------+
| Step 4/5  Male or female       |
|                                |
| [ Male                     ]   |
| [ Female                   ]   |
| [ Unknown                  ]   |
| [ Next ]            [ Back ]   |
+--------------------------------+
```

- 最初の版はハンターが選ぶ（F4）。「不明」も選べる。
- アクセシビリティ: h1「雌雄」、選択肢はラジオボタン相当、最初のフォーカスは 1 つ目の選択肢。

### H6. 内容の確認と送信（ステップ 5/5、クマのときは 6/6）

```
+--------------------------------+
| Step 5/5  Check and send       |
|                                |
| <photo> <photo> (<photo>)      |
| Kind: Boar   Sex: Female       |
| Place: (map pin) Town A        |
| Date: 2026-11-20 08:15         |
| Hunter ID: 12345               |
|                                |
| [          Send            ]   |
| [ Back ]                       |
+--------------------------------+
```

- 写真・種類・雌雄・位置（地図のピンと地名）・日時・従事者番号を表示する。交付金の実績報告に使う項目（F13）もここで確認できる（項目の詳細は要件の段階で決める）。
- 送信ボタンは押した後すぐに押せなくなる（二重送信を防ぐ）。
- 「送る」を押した後に、重複の疑いを判定する。判定中はボタンに「確認しています」と進行表示を出す。疑いがあれば H7 を出し、なければそのまま送信して H8 に進む。
- 状態: 送信中＝ボタンに進行表示 ／ 送信できない＝「送れませんでした。電波のある場所でもう一度」と、入力内容を残したまま「もう一度」ボタン。
- アクセシビリティ: h1「確認して送る」、写真に代替テキスト（「全身の写真」など）、最初のフォーカスは「送る」。

### H7. 重複の疑い（送信前の確認）

```
+--------------------------------+
| Similar report found           |
|                                |
| A similar report was sent near |
| here on the same day. Is this  |
| the same animal?               |
|                                |
| [ Different animal - send  ]   |
| [ Stop sending             ]   |
+--------------------------------+
```

- 表示文: 「近くで同じ日に、よく似た報告があります。同じ個体ではありませんか？」（Q7）。ボタンは「別の個体なので送る」「送るのをやめる」の 2 つ。
- 「別の個体なので送る」を選んだときは、依頼元の一覧で疑いの印が付く（F6・F9）。
- 「送るのをやめる」を選んだときは、撮った写真と入力内容を **下書き** としてスマホに残し、ホーム（H2）に戻る。ホームの一覧に「下書き」と表示し、開くと H6（内容の確認）から再開できる。下書きは「削除」ボタンで消せる（消すときは確認を出す）。野外で撮った写真が消えないようにするため。似ている報告の写真は、他人の報告のため表示しない（仮定。個人情報の扱いを要件の段階で確認）。
- アクセシビリティ: ダイアログ（フォーカスはダイアログ内に閉じる）、h1 相当の見出し「よく似た報告があります」、最初のフォーカスは「送るのをやめる」（誤送信を防ぐ）。

### H8. 送信完了（ステップに数えない）

- 大きなチェックのアイコンと「送りました。依頼元が確認します」。ボタンは「ホームに戻る」の 1 つ。
- アクセシビリティ: h1「送りました」、状態の変化を読み上げで知らせる。

### H9. 自分の報告の詳細（状態と却下の理由）

```
+--------------------------------+
| My report 11/15 Bear  [Back]   |
|                                |
| State: Rejected (x icon)       |
| Reason: Photo is not enough    |
|                                |
| <photo> <photo> <photo>        |
| Kind: Bear   Sex: Unknown      |
|                                |
| [   New report (retake)    ]   |
+--------------------------------+
```

- ホームの一覧（H2）から自分の報告を開くと表示する。状態（承認・確認中・却下）を文字とアイコンで示し、却下のときは依頼元が選んだ理由（R3）を表示する。
- 却下のときだけ、大きな「撮り直して新しく報告する」ボタンを出す。押すと新しい報告の作成（H3）が始まる（再報告は新しい報告として扱い、元の報告は却下のまま残る）。
- 状態: 確認中・承認のときは、ボタンを出さず内容の表示だけ。確認中のときは「送ってから n 日」と、7 日を過ぎた場合の案内（H2 と同じ文）を表示する。
- アクセシビリティ: h1「自分の報告」、h2「状態」「写真」「内容」、ランドマーク header・main、写真に代替テキスト、最初のフォーカスは「戻る」。

## 依頼元側（市町村の担当課・猟友会）

### R1. ログイン

- H1 と同じ形（同意・従事者番号の画面はない）。パソコンでもスマホでも使える。
- アクセシビリティ: h1「MonsterNote（依頼元）」、ランドマーク header・main、最初のフォーカスは ID の入力欄。

### R2. 報告の一覧

```
+------------------------------------------------------+
| MonsterNote (Requester)                    [Menu]    |
| Filter: (Checking) (Approved) (Rejected) (Suspect)   |
|------------------------------------------------------|
| Date  | Hunter   | Kind | Place  | State    | Flag   |
| 11/20 | Tanaka   | Boar | Town A | Checking | Suspect|
| 11/20 | Sato     | Deer | Town B | Checking |        |
| 11/18 | Suzuki   | Bear | Town A | Approved |        |
+------------------------------------------------------+
```

- 一覧の列: 日付・ハンター・種類・場所・状態・重複の疑いの印。確認中の報告は古い順に並べ、送られてから 7 日を過ぎたものに「7 日以上」の印を付ける（ハンターを待たせないため）。疑いの印は文字とアイコンで示す（色だけにしない）。絞り込み: 確認中・承認・却下・重複の疑い。
- スマホでは表をカード形式（1 件 1 枚）に切り替える。
- 状態: 空＝「確認待ちの報告はありません」 ／ 読み込み中＝表の形をした仮表示 ／ エラー＝「読み込めませんでした」と「もう一度」。
- アクセシビリティ: h1「報告の一覧」、表は見出しセル付き、ランドマーク header・nav・main、最初のフォーカスは絞り込み。

### R3. 報告の詳細と確認

```
+------------------------------------------------------+
| Report 2026-11-20 Tanaka                  [Back]     |
|                                                      |
| <whole body> <tail> (<chest>)                        |
| Kind: Boar (auto: Boar)  Sex: Female                 |
| Place: map  Date: 2026-11-20 08:15  Hunter ID: 12345 |
| Suspect: similar report 11/20 Sato (same place) ->   |
|                                                      |
| [ Approve ]   [ Reject ]                             |
+------------------------------------------------------+
```

- 写真（拡大できる）、種類（自動判別の結果とハンターの修正の両方）、雌雄、位置の地図、日時、従事者番号、交付金の項目。
- 重複の疑いがあるときは、似ている報告へのリンクを並べて表示し、見比べられる（F6・F7。F8 の照合結果もここに出す）。
- 「却下」のときは理由を選ぶ（例: 重複・写真が不十分・その他）。選んだ理由はハンターの報告の詳細（H9）に表示される。確認の操作の後は、元に戻せるよう「取り消す」を数秒表示する。
- アクセシビリティ: h1「報告の詳細」、h2「写真」「内容」「重複の疑い」、写真に代替テキスト、最初のフォーカスは「戻る」。

## Assumptions & Open Questions

- 「確認中」の目安の 7 日は仮の値で、試験運用の依頼元に確認して要件の段階で決める。 [assumption]
- 下書きをスマホに残す期間（例: 送るか削除するまで）は、要件の段階で決める。 [assumption]

- ハンター・依頼元のログインの方法（ID とパスワード、招待など）は、要件・設計の段階で決める。 [assumption]
- 重複の疑いの画面（H7）で、似ている他人の報告の写真は見せない前提にしている。個人情報の扱いと合わせて要件の段階で確認する。 [assumption]
- 交付金の実績報告に使う項目（F13）の具体的な内容は、要件の段階で最新のマニュアルを確認して決める。 [assumption]
